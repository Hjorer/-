# REST API для системы заказа блюд в кафе

Учебный проект по разработке RESTful API на фреймворке Laravel с разделением ролей, аутентификацией по токенам и валидацией данных.

## 🚀 Стек технологий
* **PHP 8.2+**
* **Laravel 11 / 12**
* **Laravel Sanctum** (Аутентификация)
* **MySQL / PostgreSQL**

---

## 🛠 Установка и развертывание

1. **Клонируйте репозиторий и перейдите в папку проекта:**
   ```bash
   git clone <url_репозитория>
   cd <название_папки>
   ```

2. **Установите зависимости:**
   ```bash
   composer install
   ```

3. **Создайте и настройте файл окружения:**
   ```bash
   cp .env.example .env
   ```
   *Откройте файл `.env` и укажите ваши параметры подключения к базе данных (`DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`).*

4. **Сгенерируйте ключ приложения:**
   ```bash
   php artisan key:generate
   ```

5. **Выполните миграции и заполните базу тестовыми данными:**
   ```bash
   php artisan migrate:fresh --seed
   ```

1. **Администратор:**
   * **Email:** `admin@cafe.com`
   * **Password:** `admin123`
   * **Роль:** `admin`

2. **Клиент:**
   * **Email:** `client@cafe.com`
   * **Password:** `client123`
   * **Роль:** `client`

## 🗺 Карта API Эндпоинтов

### Публичные маршруты (Доступны всем)

| Метод  | URL | Описание |
| :--- | :--- | :--- |
| `POST` | `/api/register` | Регистрация нового клиента |
| `POST` | `/api/login` | Аутентификация, выдача Bearer токена |
| `GET`  | `/api/categories` | Получить список всех категорий |
| `GET`  | `/api/categories/{id}` | Получить конкретную категорию с вложенными блюдами |
| `GET`  | `/api/dishes` | Получить список блюд (поддерживает фильтры `?category_id=X` и `?is_available=1`) |
| `GET`  | `/api/dishes/{id}` | Получить детальную информацию о блюде |

### Защищенные маршруты (Требуется заголовок `Authorization: Bearer <token>`)

| Метод  | URL | Роль | Описание |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/logout` | Любая | Выход из системы (отзыв текущего токена) |
| `GET`  | `/api/user` | Любая | Получить профиль текущего пользователя |
| `POST` | `/api/orders` | `client` | Оформить новый заказ (авторасчет суммы и фиксация цен) |
| `GET`  | `/api/orders` | `client` / `admin` | Список заказов (`client` — только свои, `admin` — все в системе) |
| `GET`  | `/api/orders/{id}` | `client` / `admin` | Детали конкретного заказа (с блюдами и ценами на момент продажи) |

### Маршруты Администратора (Требуется токен + роль `admin`)

| Метод  | URL | Описание |
| :--- | :--- | :--- |
| `POST` | `/api/categories` | Создать новую категорию |
| `PUT`  | `/api/categories/{id}` | Редактировать категорию |
| `DELETE`| `/api/categories/{id}` | Удалить категорию (каскадное удаление связанных блюд) |
| `POST` | `/api/dishes` | Добавить новое блюдо в меню |
| `PUT`  | `/api/dishes/{id}` | Редактировать блюдо (включая изменение статуса `is_available`) |
| `DELETE`| `/api/dishes/{id}` | Удалить блюдо из меню |
| `PATCH`| `/api/orders/{id}/status` | Изменить статус заказа (`pending`, `cooking`, `completed`, `cancelled`) |

## 📐 Архитектурные особенности проекта

1. **Разделение доступа (Middleware):** Безопасность эндпоинтов реализована через связку `auth:sanctum` и кастомного слоя `AdminMiddleware`, проверяющего поле `role` в таблице пользователей.
2. **Безопасность истории заказов:** В пивот-таблице `order_dish` создано поле `price_at_sale`. При оформлении заказа туда дублируется текущая цена блюда. Если администратор позже изменит цену в меню, стоимость старых заказов в истории не изменится.
3. **Единый формат ответов (API Resources):** Все ответы приложения трансформируются через классы `JsonResource`, что гарантирует строгую структуру данных для фронтенда без лишних системных полей базы данных.
4. **Валидация (Form Requests):** Входные данные изолированы и проверяются в отдельных классах запросов. Ошибки валидации автоматически возвращают код `422 Unprocessable Entity`.
5. **Глобальный обработчик ошибок (Exception Handler):** Любые системные ошибки, включая `404 Not Found` (при обращении к несуществующим роутам или ID моделей), перехватываются ядром фреймворка и отдаются клиенту в формате чистого JSON, полностью исключая отдачу HTML-страниц.
